# CardForge

CardForge 是一个手机竖屏优先、可持续加入新玩法的卡牌游戏平台。当前版本包含统一游戏大厅、游戏注册与按需加载机制、隔离失败的游戏宿主、无规则假设的共享能力，以及四款规则完全独立的可玩游戏。四款游戏的进行中状态会在本机断点续玩：刷新或关掉页面后重进，掼蛋的升级进度、二十一刻的筹码与牌靴、争焰进行中的对局与本机战绩、定鼎的身份局牌桌都会自动恢复。

大厅会把有存档的可玩牌桌提为「继续牌桌」，按最近保存时间排序；平台只读取存档信封，不解读游戏内容。所有牌桌共享同一套 AI 演出倍速偏好（1× / 2× / 4×），二十一刻支持「重复上一注」与牌局记录页签，掼蛋新增见习 / 标准 / 战术三档对手 AI。争焰在仍有可出牌时提前结束回合会二次确认，响应窗口会显示预计生命损失，本机战绩面板补全弃局数并可清空。

- 「争焰」：原创公开阵营四席对战，包含两行动回合、攻防响应、队友援护、联携状态、三档 AI、四套非对称牌组和本机战绩。
- 「二十一刻」：可配置房规的 21 点牌桌，包含多副牌靴、分牌、保险、迟投降、经典/挑战会话、基础策略提示与本机长期统计。
- 「掼蛋」：双副牌四人对家，包含牌型比较、红心级牌百搭、清墩、连续升级对局（打过 A 获胜）、托管 AI 与见习/标准/战术三档对手。
- 「定鼎」：原创身份阵营暗局，四席分为主君、辅臣、叛锋与流谋；包含回合阶段、刺击/闪避/疗元、距离装备、濒死求桃与身份奖惩（当前为 M0 规则骨架）。

四个游戏不共享 `GameState`、回合或卡牌规则，只通过平台的最小运行契约注册和加载。

## 运行

```bash
npm install
npm run dev
```

可用 `?game=<game-id>` 直接打开可玩牌桌，例如 `?game=guandan`。从大厅进入游戏后，浏览器返回键会回到大厅；无效或仍在筹备的 ID 不会进入游戏宿主。

验证命令：

```bash
npm run lint
npm run typecheck
npm test
npm run test:balance:ember
npm run build
npm run test:e2e
```

`test:balance:ember` 会以固定种子自动完成 1000 局争焰，用于观察胜率、轮数、过载、角色退场和卡牌使用分布；它是平衡回归基线，不替代规则断言。浏览器测试会自动启动本地 Vite 服务，并在手机竖屏、常见笔记本和宽桌面三种视口验证大厅、四款游戏主流程、宿主错误恢复、偏好持久化和页面溢出。本机默认使用系统 Chrome；没有安装时先执行 `npx playwright install --with-deps chromium`，再用 `PW_CHANNEL= npm run test:e2e` 改用随 Playwright 下载的 Chromium。CI 会自动安装。失败报告可通过 `npm run test:e2e:report` 打开。

## 项目结构

```text
src/
  app/                    # 平台大厅与游戏装载入口
  core/games/             # 游戏清单、注册表、最小运行契约
  shared/                 # 无玩法规则的卡牌视觉、声音、焦点、倍速偏好与基础身份类型
  games/
    registry.ts           # 平台唯一的游戏登记处
    ember-pact/           # 独立 Demo：规则、数据、AI、组件与样式
      domain/             # 可单测的纯规则层
      components/         # 只属于该游戏的表现组件
    twenty-one/           # 独立点数游戏：规则、会话、庄家流程、牌面与样式
      domain/             # 多副牌、逐手结算、挑战、统计与存档迁移
      components/         # 只属于该游戏的标准牌面
    guandan/              # 独立四人对家游戏：牌型、回合、AI 与样式
      domain/             # 双副牌、百搭、跟牌、清墩与胜负纯函数
      components/         # 适配 27 张手牌的紧凑牌面
    dingding/             # 原创身份阵营暗局：回合阶段、刺击/闪避、距离、求桃与胜负
      domain/             # 身份、牌堆、结算、濒死与存档校验纯函数
```

核心层不包含 HP、攻击、阵营、点数、牌型或传统回合阶段。它只负责“有哪些游戏”和“如何加载游戏”。四款游戏中的玩法概念全部保留在各自模块内。

更详细的依赖边界和新增游戏步骤见 [docs/architecture.md](docs/architecture.md)。
